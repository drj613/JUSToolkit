# Ally Boost (Koma Adjacency/Synergy System)

- Source guide: "Ally Boost Guide"
- Author: Majin-Tenshinhan (tips from Nuudoru)
- Version: not stated in source file
- GameFAQs FAQ id: gf-45966
- Reliability: unverified community claim source — a fan compilation of observed koma pairings, not verified against game code or official docs.

## Core mechanic

- Ally Boost triggers when a Support/Help koma that "relates" to a Battle Character (thematically — same series, related character, etc.) is placed on the deck grid so that it touches (is adjacent to) the battle koma being boosted.
- Visual confirmation: gold sparkles appear over the koma when a valid boosting neighbor is placed adjacent to it.
- The guide does not state the numeric effect of the boost (no damage/stat multiplier value given) — only that a boost occurs. Any specific magnitude is **(author unconfirmed)** / not present in this source.
- Every battle character has exactly 3 characters that can boost them (fixed list per character, not per-series-general).
- Boost relationships are defined per specific koma form/variant, not per character overall: if a character has an alternate form (e.g., a Dragon Ball character's Super Saiyan transformation, or a different panel-count koma), that variant has its own distinct set of 3 boosters, which can differ from the base form's set.
  - Example: Gokuu (base) is boosted by Gohan, Kamesennin, and Arale (Dr. Slump); Gokuu's 6-7 koma "Super Saiya-jin" form is instead boosted by Vegeta, Gohan, and Kuririn.
- Boosters can be same-series or cross-series; cross-series boosters are noted with the source series in parentheses.
- Boost relationships are not necessarily symmetric — e.g., Gintoki is boosted by Kagura, but Kagura's boosters are Gintoki, Shinpachi, and Vegeta (not a strict mirror).

## Implementation notes / gaps

- This guide covers only ~40 characters/forms — far from JUS's full roster (300+ koma). Treat as a partial reference for the boost-pairing data model, not a complete table.
- No numeric boost magnitude, stacking rule (e.g., what happens with multiple valid boosters adjacent at once), or range/adjacency-shape (orthogonal vs. diagonal touching) is specified anywhere in the source — these must be sourced from another guide or reverse-engineered from game code.
- Data model implication: boost eligibility should be keyed by (character, specific koma form/variant) → set of exactly 3 eligible booster koma identities, not by character alone, since transformations change the eligible set.
