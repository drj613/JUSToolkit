DJ plays this game and knows it well. Game-behaviour questions that would cost a wake of blind
runtime probing can often be answered in one sentence. **Ask.**

Worked example, 2026-08-18: I was letting matches run hoping to catch a status-family effect
firing — one hit in ~10 minutes of play. DJ volunteered that Goku's 4-koma inflicts a freeze
via up+X. Aiming at that named move produced three status dispatches in four short reps, and
took the status side of the two-channel model from n=1 to n=4.

**Why:** runtime probing is good at *measuring* a phenomenon and bad at *reaching* one. Knowing
which move produces which effect, how a mechanic is performed, or what a mode is called is
exactly the input that turns an open-ended hunt into a targeted test. That is the same
distinction as [[clean-evidence-skips-the-check]] in reverse — the instrument is fine, the
stimulus is the missing half.

**How to apply:** park questions in beads labelled `owner-question` (see the standing bead
`jus-law`), so the ledger loop surfaces them in the morning batch rather than interrupting.
Keep each question specific and say what it unblocks, so DJ can answer in a line. Don't sit on
a question for a wake because it feels like an interruption — asking is cheaper than probing,
and DJ asked to be asked.
