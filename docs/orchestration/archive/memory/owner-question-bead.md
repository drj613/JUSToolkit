The owner has deep JUS game knowledge and wants to be asked. Any question a player would simply know goes
into **`br` bead `jus-law`** (opened by the runtime loop), which the ledger loop surfaces to them each
morning. Do not carry such questions as open research threads or burn wakes measuring them.

**Why:** several wakes have been spent bracketing things the owner could confirm in one line — じかん units,
which rule modes are real, whether a status ticks. Their answer is ground truth and outranks
CONFIRMED-from-disassembly for *behaviour* (same tier as [[koma-system-observed-behavior]]).

**How to apply:** phrase each item as **confirm/deny, not an open question** — state the claim and what
answer would break it. Add them as they arise rather than batching at end of wake. Good candidates: what a
move does, which modes/rules exist in play, whether an effect is visible, what a UI element means. Bad
candidates: addresses, struct offsets, anything only the disassembly can settle. See
[[escalation-path]] for genuinely blocking questions, which still go to the PR route.
